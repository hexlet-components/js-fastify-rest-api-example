# Каталог курсов по контракту

Пример для курса REST API на Fastify и TypeScript находится в этом каталоге. Он использует отдельный PostgreSQL, Drizzle и контракт TypeSpec. Основное приложение репозитория запускается независимо.

## Запуск

Понадобятся Node.js 26 и Docker Compose. Команды выполняются из каталога `contract-first`.

```sh
npm ci
docker compose up -d --wait
npm run generate
npm run check
npm start
```

Сервер слушает `http://127.0.0.1:3000`. Документ доступен по адресу `/openapi.json`, документация по `/docs`. При первом подключении пример создаёт таблицы и добавляет три курса и один урок. Повторный запуск сохраняет данные PostgreSQL в именованном томе Compose. `DATABASE_URL` позволяет подключить другую учебную базу. По умолчанию используется `postgres://catalog:catalog@localhost:55432/catalog`.

Все курсы доступны для чтения. Токен определяет права изменения курса, доступа к своим связям и операциям экспорта. Пользователи 1 и 2 заданы как учебные личности. Скрипт выпускает токен без регистрации и проверки пароля. Такой способ нужен только для локального изучения Bearer и JWT.

```sh
npm run token -- 1 courses:write
```

Скопируйте последнюю строку вывода в переменную `TOKEN`. JWT_SECRET по умолчанию служит открытым учебным секретом. Для любого внешнего размещения нужен собственный секрет.

```sh
curl -i http://127.0.0.1:3000/courses \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Idempotency-Key: course-1' \
  -H 'Content-Type: application/json' \
  -d '{"title":"HTTP","description":null}'
```

Создание возвращает 201 и Location. Повтор с тем же телом и ключом возвращает прежний результат в течение 24 часов. Пользователь и операция входят в область ключа. Конкурентный повтор и результат хранятся одной транзакцией PostgreSQL с блокировкой по ключу.

## Стадии курса

| Команда | Содержание |
| --- | --- |
| `npm run start:setup` | Пустой сервер со служебным `/health` |
| `npm run generate:minimal`, `npm run start:minimal` | Один GET по минимальному TypeSpec, тип обработчика, вход и ответ |
| `npm run generate:crud`, `npm run start:crud`, `npm run test:crud` | CRUD без аутентификации и ключей идемпотентности, собственная таблица crud_courses |
| `npm start` | Полный каталог с защищёнными изменениями и подготовленными службами |
| `npm run start:versions`, `npm run test:versions` | Два несовместимых представления `/v1` и `/v2`, два документа и SDK |

Все стадии используют порт 3000 и запускаются по одной. Общая команда `npm run generate` получает артефакты всех стадий. `main.tsp` и дополнительные контракты являются исходниками, каталоги `generated` и `tsp-output` воспроизводятся генераторами. Сохранённый клиент `baseline/sdk` при генерации не меняется.

Для самостоятельной работы по страницам команда `npm run seed:pagination` подготавливает четыре записи, включая два курса с названием Pagination duplicate. Повтор команды сохраняет эти четыре записи без дальнейшего добавления.

## Проверки

```sh
npm test
npm run contract
npm run compatibility
```

Для `contract` нужен `uvx`. Команда запускает закреплённый Schemathesis, поднимает настоящий HTTP-сервер на случайном локальном порту и проверяет выбранные операции каталога. Для части защищённых операций сгенерированные запросы достигают только отказа без токена. Сценарии файлов, доступа, связей, конкурентной записи, 204 и фоновой работы проверяются дополнительно в тестах через Fastify inject. Сгенерированные случаи ограничены выбранными операциями и выбранным числом примеров.

Для `compatibility` нужен `oasdiff` в PATH. В окружении с mise его можно запустить отдельной командой.

```sh
mise x github:oasdiff/oasdiff@1.34.1 -- npm run compatibility
```

Проверка сравнивает сохранённый OpenAPI с текущим, подтверждает отказ при намеренном удалении операции и вызывает текущий сервер сохранённым SDK. Фикстура `versions` отдельно показывает два несовместимых представления курса, поле title в v1 и поле name в v2. Она использует общий учебный ответ и два контракта, самостоятельного хранения у неё нет.

## Экспорт и уведомления

POST `/exports` принимает `{ "format": "json" }` или `{ "format": "csv" }` и ключ идемпотентности. Ответ 202 содержит Location операции. Ресурс операции описывает pending, running, succeeded и failed. Готовый исполнитель запускается вместе с `npm start` и сохраняет результат в PostgreSQL. После перезапуска pending-задания продолжаются. В учебном исполнителе нет восстановления задания, прерванного уже в running. Отказ демонстрируется запуском `FAIL_EXPORTS=true npm start`; эту настройку следует убрать перед следующим запуском.

POST `/courses/{courseId}/publication` принимает expectedVersion. После успешного изменения сервер записывает событие course.published. Отправка настроена отдельно.

```sh
npm run receiver
```

В другом терминале запустите API с адресом получателя.

```sh
WEBHOOK_URL=http://127.0.0.1:4000/events npm start
```

Контракт уведомления хранится в `webhooks/main.tsp` и порождает отдельный OpenAPI и тип WebhookEvent. Получатель проверяет подпись исходного тела HMAC SHA-256 и идентификатор события. Повторная попытка отправителя сохраняет id. Получатель хранит обработанные id в Set до завершения процесса, повторный запуск очищает этот список. Подпись проверяет владение секретом, бессрочная защита от воспроизведения старого события здесь не реализована. Повтор отправки не обещает однократного внешнего эффекта.

При `RECEIVER_FAIL=true npm run receiver` сервер отвечает 503. Отправитель сохраняет событие для следующей попытки. Локальный пример посылает события одному настроенному получателю и последовательно выполняет фоновые проходы. Полноценная инфраструктура подписок и доставки не входит в пример.

Ограничитель включается командой `RATE_LIMIT=true npm start`. Для `/me` каждый пользователь получает три запроса за секунду. Отказ имеет статус 429, Problem Details и Retry-After. Учёт лимита хранится в памяти одного процесса.

## Границы проверки контракта

Ajv Fastify проверяет запросы по схемам glue. Общий адаптер читает обязательность тела и media type из OpenAPI. Для format binary он проверяет Buffer после парсинга image/png. Для nullable-ссылок OpenAPI 3.0 адаптер переводит allOf в явную альтернативу null при регистрации runtime-схем. Исходный документ остаётся результатом TypeSpec.

Response-validation работает со строгими параметрами без преобразования, удаления полей и подстановки значений. Эта проверка исполняется после обработчика и не откатывает сохранённые данные. Строки, Buffer и пустые ответы требуют проверки фактического HTTP. Hey API не включает 303 в успешный Reply, поэтому обработчик перенаправления использует FastifyReply и отдельный HTTP-тест. Проверка заголовков и тела перенаправления не выводится из одного успешного tsc.

Обложки хранятся в PostgreSQL для воспроизводимого примера. Сервер проверяет PNG-сигнатуру и предел в один MiB. Полная проверка изображения, внешнее хранилище и потоковая загрузка остаются отдельными задачами. Экспорт CSV показывает базовый формат и не защищает от формул при открытии в табличном редакторе.

Остановите API и получателя через Ctrl+C, затем остановите БД.

```sh
docker compose down
```

Команда сохраняет учебные данные в томе. `docker compose down -v` удаляет их и нужна только при намеренном сбросе своего локального примера.
