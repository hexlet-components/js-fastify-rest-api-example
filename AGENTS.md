# Каталог курсов REST API

Основное приложение находится в src/, контракт в main.tsp. Генерация получает OpenAPI в tsp-output/ и полный RouteHandlers с SDK в generated/. Производные файлы коммитятся в стиле генератора. Исходный код форматируется oxfmt и проверяется oxlint.

Перед изменением HTTP-поведения меняется TypeSpec, затем запускаются pnpm run generate, pnpm run check и pnpm test. Итоговый объект обработчиков реализует полный RouteHandlers. Проверка ответа дополняется фактическими HTTP-тестами бинарных тел, перенаправления и пустого 204.

Данные хранятся в отдельном PostgreSQL. Подготовленная начальная миграция migrations/0001.sql применяется при открытии хранилища, повтор сохраняет данные. Учебные значения подключения находятся в .env.example. Тесты не загружают .env, а используют DATABASE_URL процесса. Каждый тест создаёт свои записи, служебные данные остаются в учебной базе.

Перед pnpm test нужна работающая БД из docker compose up -d --wait. make lint, make generate-check, make contract-test, make compatibility-test и make smoke-test проверяют код, воспроизводимость генерации, HTTP, старый SDK и образ соответственно. Полный набор быстрых и сетевых проверок задаёт hk.pkl. Git-хуки сохраняют непроиндексированные изменения.

Стартовые стадии в starters/ вводят setup, minimal и crud до полного приложения. versions/ демонстрирует два несовместимых представления с независимыми SDK. baseline/ хранит прежний клиент и документ, обычная генерация их не меняет. webhooks/ содержит контракт HTTP-получателя.

JWT определяет учебную личность. Чтение курсов публичное, изменение требует разрешения и владения. Ключ идемпотентности учитывает пользователя и операцию, эффект и результат сохраняются одной транзакцией. Получатель вебхуков помнит события до завершения процесса. Исполнитель продолжает pending, восстановление прерванного running не реализовано. Эти границы сохраняются в README и тестах.

Коммиты идут по Conventional Commits. Доставка Git и публикация приложения выполняются отдельно. Отправка образа и make deploy в own-heroku требуют предусмотренного китом разрешения.
